## Proposed lib additions
- `lib.codec` / `lib.warmups_codecs` (D25 re-measure): 341 + 88 regexes compiled at import = ~0.2 s of a 0.73 s sequential single. Compile lazily (e.g. a `functools.cache`d `_re(name)` accessor) -- it is now the biggest fixed cost of every script-lane solver.
- `lib.codec` import is ~0.3 s, almost all of it from ~340 module-level `re.compile`s (cProfile, D24 single). Compiling lazily would save that on every script-lane solver start.
- Solver skeleton: when `group_by_set` gives one group, split the questions by artifact across forked workers (independent members), like D24 solve.py `main()`.
- `lib.common.gm_error_body(artdir) -> bytes|None`: detect a GM error JSON (`rate_limited`, ...) saved in place of an
  artifact, so every solver fails loudly. Better still: the harness download step (hctf/hb_timed.py) should retry on
  `{"error":"rate_limited"}` and never save it as the artifact. That would have saved this timed attempt.
- `lib.common.iter_entries(root, leaf_ext=...)`: don't load a member just to sniff for a nested zip when its name has a script/text extension (.js/.ps1/.py/.vbs/.cmd/.bat/.sh/.mjs/.php/...). Today it decrypts every AES member of a Mastery bundle up front (375 PBKDF2 = ~0.2 s locally, many times that on Homebase), and each forked set repeats it. See `_iter_entries` in this solve.py.
- `lib.common._zip_open`: prefetch WinZip-AES keys for all members in parallel (salt = bytes after the local header; `hashlib.pbkdf2_hmac` in a ThreadPoolExecutor), as D23 solve.py `_prefetch_keys` does. Every script-lane Mastery solver pays ~1 ms x members serially today.
- `lib.codec`: ~295 module-level `re.compile`s cost ~0.3 s per solver start, and `_find_codecs_uncached` runs ~16 regex probes per text (4669 searches / 287 texts = 0.4 s on the D23 Mastery). Compile lazily and gate each detector on a cheap substring test (`'Codec_' in text`, ...).
- `lib.codec.find_codecs`: try the direct `_CODEC_RE` + `material_text` + `decode` reading first and return early on a plan, before the carrier/C#-fold/peel fallbacks (each script-lane solver pays ~27 ms per member for them otherwise). Also: `peel_plan`'s wall-clock `budget` makes results depend on host load.
