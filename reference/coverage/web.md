# Web coverage atlas

Lane: a LIVE challenge-owned target per question (`targets[{id:"Target N", url}]`, no artifact), one `proof-N`
question per target, answer = the token `proof_<32 hex>` the app prints once the bug is exploited (`trim`). One
classic bug per lane-day, named by a title pun: D01 exposed backup, D02 IDOR, D03 SQLi (paren-wrapped LIKE), D04 path
traversal to `/run/huntress/objective.txt`, D05 unprotected feature route, D06 reflected XSS (server-judged "isolated
callback"), D07 stored XSS (real moderator bot), D08 session fixation, D09 CSRF (server-judged by
`Sec-Fetch-Site: cross-site`), D10 unrestricted upload rendered by a `{{field}}` template preview. Since D05 every
target is the same kit: `/api/clues` names `feature_route`, `secondary_route`/`render_route`/`preferences_route`,
`current_role` + concept keys (`callback_nonce`, `moderator_data_route`/`receipt_route_template`, `session_hint`,
`preview_guide`/`upload_policy`/`upload_shape`); the concept keys often spell the request shape in prose; stated
policies ("txt only", csrf_token) have been decorative. Routes return JSON errors naming the missing piece; success =
JSON with `evidence: proof_...` (or the proof in a rendered page). Mastery = today's bug + 2 earlier lane-days (3
targets since D08), described only by today's prompt. Pace: D01-D03 cal. 19, D04-D05 cal. 20, D06-D08 cal. 21,
D09-D10 cal. 22 (~2-3 lane-days per calendar day) -> priority 1 below = the bugs most likely in D11-D18.
Arc: info-disclosure -> access control -> injection -> file read -> access control -> XSS (reflected, stored) ->
session fixation -> CSRF -> upload. The client-side/session block looks closed; D10 turned server-side and already
showed a template engine evaluating `{{objective}}`, so next most likely: SSTI, OS command injection, SSRF, XXE,
JWT / signed-cookie forgery, role tampering / mass assignment, then open redirect, DOM XSS, deserialization.
Snapshot 2026-10-22 (after D10). `lib/web/` now exists (`handlers/__init__.py`: `_KEY_MAP` clue-key regex ->
handler, `_HANDLERS` = only `session_fixation`, plus a `default` ladder; `lib/web/__init__.py` races handlers +
every earlier web day's `answer()`; `hctf web-harden`). `hctf prebuild` still has NO `web` lane and no `web:*` keys
exist in `.run/prebuild-state.json` -> every prebuild gap below is still pending.

Status legend: `seen Dnn` = GM-confirmed lane-day (solver in `challenges/<cal-day>/web-*/solver/solve.py`).
`gap` = nothing reusable in lib (D09 `csrf()` / D10 `upload()` live only in their day22 solve.py, not lib). Prebuilt web modules must be PURE (no `urllib.request`): bodies in -> request plan
`[(method, path, headers, body)]` out; response in -> proof or next hints. The solver does the fetching.
