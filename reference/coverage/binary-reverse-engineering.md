# Coverage atlas -- binary-reverse-engineering (as of D16, 2026-10-16)

Scope: what a D17+ `evidence.zip` group could be, how we would recognise it, which standard tool answers it, and how ready we
are. Grounded in `reference/techniques/binary-reverse-engineering.md` (lane log D1-D16), `challenges/day16/binary-wasm-up/solver/`,
`lib/binary.py` (`hcfg_scan`/`hcfg_find`, `packer_info`, `unpack_upx`, `go_buildinfo`, `go_pclntab_funcs`, `rustfilt`, `macho_facts`,
`recover_return_constants`, `ghidra_decompile`, `jar_app_classes`, `wasm_layout`) and `tests/data/binary_fixtures/TARGETS.json` (all 9 targets have fixtures).

Progression so far: D1-D14 = one new compiled language per day (container nearly always ELF64 x86-64, HCFG blob re-stored per
language); D15-D16 = "ONE SOURCE, TWO BUILDS" pairs with a `<qualifier>_` id prefix taken from the file-name tag (D15 C ELF
`stripped`/`symbolized`; D16 WebAssembly `compact`/`direct` = two codegens of one function, first non-native container since the
jars: labels `wasm`/`wasm32`, HCFG RAW in active data segment 0). Expect the pair axis to continue (static/dynamic, O0/O2,
PIE/no-PIE, packed/unpacked, x86-64/AArch64) and more non-ELF containers (Mach-O, eBPF, bytecode). Asked field names are a small
fixed pool (config_*, format, machine, architecture, elf_class, elf_type, endianness, entry_point, symbols, section_names,
disassembly, has_symtab, has_cpp_*, has_hcfg_section, hcfg_offset, hcfg_version, xor_key_hex, metadata_version,
compression_methods); the prompt's language theme has not been asked since D4. So for D17+ the biggest risks are (a) a twist that
hides the HCFG from a byte scan (packing, real crypto, stack-built), (b) a new container/arch whose LABEL we have never spelled
(Mach-O, eBPF, AArch64, MIPS...), (c) a new field family (imports/exports, memory/table "doors" -- the D16 prompt's theme --,
build-id, protections), (d) a pair qualifier that itself contains `_` (`x86_64_machine`) breaking a split-at-first-`_` router.

Tool legend: **[I]** installed (`source bin/env.sh`; checked with `which`/`ls`), **[M]** missing.
Installed: readelf/objdump/nm/c++filt/strings/objcopy (binutils x86-64 + aarch64-linux-gnu-objdump), llvm-18 (llvm-objdump-18,
llvm-readobj-18, llvm-otool, llvm-lipo, llvm-nm, llvm-dwarfdump, llvm-cxxfilt-18 under /usr/lib/llvm-18/bin), file, binwalk, upx 4.2.4,
rizin 0.9.1 (`bin/rizin`, `rz-bin`, `rz-asm`, `rz-find`, `rz-diff`) + radare2/rabin2, Ghidra (`bin/analyzeHeadless`, processors incl.
AARCH64/ARM/MIPS/PowerPC/RISCV/Sparc/x86/JVM/Dalvik), GoReSym, rustfilt, swift-demangle, nim-demangle, ilspycmd, dotnet, java/javap,
jadx, dex2jar, apktool, pyinstxtractor, pycdc/pycdas, autoit-ripper, hbc-decompiler, gdb + gdb-multiarch, ltrace/strace, yara, wabt (wasm-objdump/wasm2wat/wat2wasm/wasm-decompile), floss (.venv), luac,
7z, xxd; venv python: capstone, unicorn, angr, lief, pyelftools, pefile, dnfile, pycryptodome, pyzipper, xdis/uncompyle6/decompyle3,
lz4, yara. Cross compilers: aarch64-linux-gnu-gcc-15, clang-18 (no lld/wasm-ld: other targets compile to `.o` only).
Missing: qemu-user(-static), wasm-ld/lld, wasmtime, capa, Detect-It-Easy (diec), de4dot, monodis, erlang (beam_disasm),
unluac/luajit-decompiler (luac present), blutter, srecord (srec_cat), binutils-multiarch, checksec, python zstandard/brotli, rzpipe/r2pipe.
