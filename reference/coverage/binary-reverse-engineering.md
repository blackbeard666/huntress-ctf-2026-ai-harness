# Coverage atlas -- binary-reverse-engineering (as of D18 post-run, 2026-10-18)

Scope: what a D19+ `evidence.zip` group (or backfilled old-group id) could be, how we would recognise it, which standard tool answers it, and how ready we
are. Grounded in `reference/techniques/binary-reverse-engineering.md` (lane log D1-D18), `challenges/day18/binary-flow-state/solver/`,
`lib/binary.py` (`hcfg_scan`/`hcfg_find`, `packer_info`, `unpack_upx`, `go_buildinfo`, `go_pclntab_funcs`, `rustfilt`, `macho_facts`,
`recover_return_constants`, `ghidra_decompile`, `jar_app_classes`, `wasm_layout`) and `tests/data/binary_fixtures/TARGETS.json` (all 9 targets have fixtures).

Progression so far: D1-D14 = one new compiled language per day (container nearly always ELF64 x86-64, HCFG blob re-stored per
language); D15-D16 = "ONE SOURCE, TWO BUILDS" pairs with a `<qualifier>_` id prefix from the file-name tag (C ELF
`stripped`/`symbolized`; WebAssembly `compact`/`direct`, labels `wasm`/`wasm32`); D17 "Decoder Ring" = back to ONE new language
(Ada/GNAT ELF, HCFG RAW in `.rodata`, nothing new to decode) + BACKFILL #2 (160 -> 204 ids, 11 per old group) that re-asked
EARLIER DAYS' single-solve facts (d01 marker/recover_code, d02 mangled_score_symbol/typeinfo_symbol, d04 has_go_runtime, d05
has_rust_mangled_symbol, d06 methods/access_flags, d07 method_count/has_coroutine_runtime) and a NEW label field `hcfg_storage`
(an ENUM after the organizers' mid-day contract revision: base64 / raw_hcfg_section / raw_const_array / wasm_data_segment / raw,
picked by an ordered rule list in the question text; before the revision ~10.9k free-text probes failed). TT/Mastery: d01 re-rolled
STRIPPED -> `recover_code` `none`. **D18 "Flow State"** = ONE Fortran (gfortran) ELF, exactly as forecast (prebuild
`fortran-gfortran-member`): HCFG RAW in `.rodata` (`encoded_config.4`, offset 8512 in every variant), 216 ids = 204 + 12 new-group
ids, NO backfill, CORRECT at T+11 s from the carried-over solver; TT/Mastery (4 sets) first try, d01 NOT stripped this time. The
D18 theme ("reconstruct the call graph, read the API intent at each edge, prove no injection") was unasked; the binary's flow =
getenv(`HUNTRESS_HOST_MODEL`) -> `_gfortran_select_string` case table -> indirect `call rax` to `event_{decoy,sandbox,failure,
success}` -> trace JSON (`fortran_indirect_flow_trace`, effects `modeled_process_access_no_injection`). Every member since D2
embeds such a `huntress.binary.dynamic_trace.v1` template -- a backfill can ask branch/event/family/effects facts.
Lessons for D19+: (a) the next backfill will most likely reach D8-D18's own day facts (Swift/Nim/Zig/D/FPC/Crystal/ObjC/pair/
wasm/Ada/Fortran identity booleans, symbol names, class/selector
lists, wasm imports/exports) -- the "theme" of a day is answerable LATER on its old group; (b) the new-day member keeps being a
plain ELF whose ids the carried-over solver already answers (D17 group banked at T+18 s, D18 at T+11 s); (c) label fields with no derivable
spelling (`hcfg_storage` raw, D3 `pe_cli`) are the real time sink -- and the organizers fix them by REVISING THE CONTRACT
(enum + rule text), so re-pull it instead of guessing; (d) location/storage-classification fields (`hcfg_offset`,
`hcfg_storage`) need offset -> section/segment mapping on every container. Asked field names: config_*, format, machine, architecture,
elf_class, elf_type, endianness, entry_point, symbols, section_names, disassembly, marker, recover_code, has_symtab, has_cpp_*,
has_go_runtime, has_rust_mangled_symbol, has_coroutine_runtime, mangled_score_symbol, typeinfo_symbol, methods, access_flags,
method_count, has_hcfg_section, hcfg_offset, hcfg_version, hcfg_storage (enum), xor_key_hex, metadata_version, compression_methods.
Remaining risks: (1) more per-language fact backfills, (2) a twist that hides the HCFG from a byte scan (the D17 "decoder" theme
did not materialise but stays plausible: packing, real crypto, stack-built, per-string encryption, API hashing), (3) a new
container/arch label (Mach-O, eBPF, AArch64...), (4) more pair days with `_`-containing tags, (5) the D18 theme family as
fields: call-graph edges, indirect-call targets, API intent / `has_injection`, env-gated sandbox/decoy branches, trace family.
