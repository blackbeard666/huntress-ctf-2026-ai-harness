# Coverage atlas -- binary-reverse-engineering (as of D20 post-run, 2026-10-20)

Scope: what a D21+ `evidence.zip` group (or backfilled old-group id) could be, how we would recognise it, which standard tool answers it, and how ready we
are. Grounded in `reference/techniques/binary-reverse-engineering.md` (lane log D1-D20), `challenges/day20/binary-resourceful/solver/`,
`lib/binary.py` (`hcfg_scan`/`hcfg_find`, `packer_info`, `unpack_upx`, `go_buildinfo`, `go_pclntab_funcs`, `rustfilt`, `macho_facts`,
`recover_return_constants`, `ghidra_decompile`, `jar_app_classes`, `wasm_layout`) and `tests/data/binary_fixtures/TARGETS.json` (all 9 targets have fixtures).

Progression so far: D1-D14 = one new compiled language per day (container nearly always ELF64 x86-64, HCFG blob re-stored per
language); D15-D16 = "ONE SOURCE, TWO BUILDS" pairs with a `<qualifier>_` id prefix (`stripped`/`symbolized`, `compact`/`direct`);
D17 Ada ELF + BACKFILL #2 (160 -> 204 ids: old days' single-solve facts re-asked on their groups + the `hcfg_storage` enum after a
mid-day contract revision); D18 Fortran ELF (theme "call graph / no injection" unasked, CORRECT T+11 s). **D19 "Jack in the Box"
(static-unpacking)** = ONE GnuCOBOL ELF (11 KB, `libcob.so.1`, stripped) whose HCFG is NOT in the image: a `PK19` overlay is
appended after the section-header table (`PK19|ver|k1|k2|pad|u32le len|sha256[32]|packed`, unpack `ror8(b^k2,3)^k1`, sha256-check,
HCFG at out[0]). FIRST day whose prompt theme WAS asked on its own group: config_* only after unpacking + NEW `overlay_offset`
(offset of the last magic) / `overlay_size` (file length - offset). The question text spelled the whole stub; 228 ids = 216 + 12,
no backfill; CORRECT T+2:25, TT 4 s / Mastery (5 sets) 10 s first try; overlay 10808/424 constant across variants.
**D20 "Resourceful" (resources-and-overlays)** = ONE Haskell ELF (GHC 9.12.2, 1.2 MB, dynamic libgmp, not stripped) + a 463-B
`RS20` overlay at e_shoff+e_shnum*64: `RS20|ver@4|u32le res_len@8|u16le scratch_len@12|sha256(scratch)@16|HCFG resource@48 (RAW)|
scratch` ("private-scratch:<campaign>:inert-only"). 240 ids = 228 + 12; NEW `hcfg_resource_size` (= u32le @8, 380). The prebuilt
RS20/question-spec unpacker + raw HCFG scan banked 239 ids at T+27 s; one field branch -> CORRECT T+49 s, 0 wrong; TT 4.8 s /
Mastery 9.3 s first try; overlay constant across variants. D19-D20 = a "hidden storage" arc (packed overlay -> resource overlay;
prompt: "resources, overlays, bytes past the end of the sections ... map every boundary").
**Forward hints still open**: `neko_bytecode` in the format enum (unseen through D20); d07 `method_count` text: "for Day 26 use the
primary classfile named by that unit" (=> a JVM classfile member on D26 whose primary class is named by the question, not the
manifest). No new magic token in the D20 contract (no `XX21`): D21's twist is unannounced.
Lessons for D21+: (a) read the longest question of each new family first -- it is the layout spec; (b) every `*_size`/`*_offset`/
`*_sha256` id maps to ONE named header field: parse the spec into a struct and expose every field; (c) grep each contract for
tokens/days that are not today's; (d) header ids of the new member are answered by the carried-over solver; the twist is the new
field family; (e) `none` only for ABSENT things; (f) unguessable labels get fixed by contract revision -- re-pull.
Asked field names: config_*, format (enum), machine, architecture, elf_class, elf_type, endianness, entry_point, symbols,
section_names, disassembly, marker, recover_code, has_symtab, has_cpp_*, has_go_runtime, has_rust_mangled_symbol,
has_coroutine_runtime, mangled_score_symbol, typeinfo_symbol, methods, access_flags, method_count, has_hcfg_section, hcfg_offset,
hcfg_version, hcfg_storage (enum), xor_key_hex, metadata_version, compression_methods, overlay_offset, overlay_size,
hcfg_resource_size.
Remaining risks: (1) D21 continues the storage arc with an unannounced container spot (section slack/caves, ELF notes,
compressed sections, multi-entry resource tables, appended archives, PE .rsrc/certificate) -- the question will spell the layout;
(2) a backfill asking RS20/PK19 header facts (scratch_size, scratch_sha256, overlay_version, k1/k2, packed_length) or
`hcfg_storage` for overlay-stored blobs; (3) Neko bytecode labels (architecture/machine for a VM); (4) D26 JVM classfile member;
(5) per-language fact backfills (D8-D20 groups).
