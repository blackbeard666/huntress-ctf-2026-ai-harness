# script-analysis — coverage atlas (D1-D17 seen vs. D18+ candidates)

Updated 2026-10-17 after D17 (1139 ids, 127 members; D17 added AutoHotkey `.ahk`, all modes first try, single T+13 s); gaps
re-queued 2026-10-18 after the D17-night prebuild (7 built, 1 given up, 1 pending retry). Read with `reference/techniques/script-analysis.md` (what the GM
actually asked) — this file is the BREADTH map: which common script/malware-script CTF concepts we have met, which we
have not, how to fingerprint and statically decode each, and what to prebuild/install before they drop.

Context that drives the likelihood column:
- Since D8 every new language is a **v=3 polyglot**: 4 fixtures `polyglot-<lang>-{benign-utility,downloader,launcher,
  staged-chain}` (44 ids: role/attack/adapter/campaign/steps/stage-count/host-profile/obfuscation/stage-profile/
  next-language + url) plus sometimes one `host-<profile>-<lang>` file. All answers are plan-verbatim; the plan sits
  behind `HUNTRESS_ANALYSIS_V1:<B64|HEX|HB64|FRAG>-..` in the host's comment syntax + a `descriptor_<id>` literal.
  The carried solver (`challenges/day17/scripting-fetch-quest/solver/solve.py`, `V3_MARK` / `_v3_peel` /
  `analyse_v3`; ran unchanged D9-D17) is language-agnostic **as long as** the marker is ASCII/UTF-8 in raw bytes, on one line, peelable by hex/base64/
  reverse within 3 layers. The real D18+ risk is not a new language — it is a new **carrier/encoding/container**, a
  new **synthetic-label family** (D2-D7 era), or a **GM label-regime flip** on an old one (D15 pool-keyed, D16 date-keyed
  batch `expansion`: same bytes, new label). Narrative prompts (D8 siblings, D15 phantom store, D16 "prove which are
  truly equivalent, expose the variant that changed the plot", D17 "reconcile source fetch targets with the generated network
  evidence, find the indicator on only one side") have never been asked -- yet; rows 66 and 68 prepare for it. D17 is the
  first prompt naming a SECOND evidence type (network) that was not shipped: the likeliest next twist is that it ships.
- Family names may contain `_` (D14 `polyglot-msbuild_xml`); host profiles seen: standalone, wsf_jscript, wsf_mixed,
  hta_jscript, php_webshell, sct_scriptlet, lua_openresty, perl_cgi, ruby_rack (D17: no host file). D14 picked a Windows LOLBin (MSBuild), D10 a WMI
  host (MOF), D13 a macOS host: the organizers alternate "language" days and "trusted-host abuse" days. D15-D16
  went Perl -> Ruby (+ CGI/Rack web hosts), D17 back to a Windows automation language (AutoHotkey, sibling of D12 AutoIt).
  Languages still unpolyglotted: PowerShell v=3, VBA, Tcl, Go, Groovy/Kotlin, R, C#/F# scripts, CI YAML, Makefile/Docker.
- ~14 drops left (D18-D31).
  Paths below: `$R=/home/testpwn/huntress-2026`; `source bin/env.sh` puts `bin/` on PATH
  (pwsh 7.6.6, box-js, js-beautify, webcrack, pycdc/pycdas, 7z, autoit-ripper, ilspycmd). `R/.venv/bin` holds oletools,
  msoffcrypto-tool, decompyle3/uncompyle6/xdis, pyinstxtractor-ng, LnkParse3, chepy, lxml, and **binary refinery 0.11.1**
  (AST deobfuscators `ps1` `js` `vba`, batch emulator `bat`, `wshenc`, `xlmdeobf`, `xtone`, `xtchm`, `lnk`, `xtpyi`,
  `pyc`, `a3x`, `xtnode`, `decompress`, `b64`, `xor`, `rot`...). Usage: `.venv/bin/<unit> < file`.
